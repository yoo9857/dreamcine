# 시리즈 등록 — 세 단계 흐름

사용자 요청: 한 화면에 압축하면서 글자와 입력 공간이 좁아졌으므로 1·2·3 순차 등록으로 전환.

## 변경

- 1 작품 선택 → 2 영상 준비 → 3 정보 입력. 현재 단계, 선택 완료 표시, 다음 단계 준비 조건을 상단에서 확인한다. 완료한 단계와 변경 버튼으로 이전 내용을 수정할 수 있다.
- 가로 세 열을 없애고 최대 960px 작업 공간에 현재 단계만 표시한다. 긴 작품 제목은 목록에서 줄바꿈하고 영상 제목 입력과 AI 도구 버튼의 공간을 확보한다.
- 새 시리즈 생성 성공 후 영상 단계로 이동한다. 기존 시리즈는 선택 후 다음 버튼으로 진행한다. 영상 선택 전 정보 단계는 잠근다. 단계 이동으로 저장 API를 호출하지 않는다.
- 이전 단계의 폼·입력·업로더는 숨기되 마운트를 유지한다. 이전/다음 이동, 작품 변경 중에도 제목·AI 도구·직접 입력·선택 영상이 유지되고 진행 중 업로더는 제거되지 않는다. 새로고침 후 복구를 제공하는 변경은 아니다.
- 단계 이동 시 제목으로 초점을 옮긴다. 저장·시리즈 생성 중 이동을 잠그고, 실패 시 입력 유지·오류 초점 이동을 제공한다. 모바일 하단 고정 버튼, PC sticky 작업 버튼, reduced-motion 대응 전환을 포함한다.
- 기존 AI 도구 선택·직접 입력, 형식 드롭다운, 선택 항목 접기, 초안 저장 후 공개 흐름은 유지한다. 영상 단계 Enter 제출은 저장 API를 호출하지 않는다. 별도 등록 모달은 기존 동작을 유지한다.
- API·DB·권한·워커·업로드/변환 계약 변경과 마이그레이션 없음. 임시 로컬 미리보기 라우트는 검사 후 삭제한다.

## 검증

- 단계 흐름 Vitest 14개 통과: 단계 조건, 초점, 뒤로/앞으로, 입력·선택 유지, 업로더 유지, 생성 후 이동, 검색, 저장 중 잠금·실패 복원, 영상 단계 Enter 제출 차단, 계속 버튼과 등록 버튼 DOM 분리.
- 공용 스튜디오 25개·등록 모달 1개 통과. 로컬 실제 컴포넌트 브라우저 1개 검사에서 320·390·768·1024·1366·1440px의 세 단계, 최소 입력 폭, 가로 넘침, 모바일 버튼 위치와 값 보존 확인. PC·모바일 스크린샷 검수.
- 별도 로컬 브라우저에서 위 여섯 화면 크기의 새 작품 형식 선택·이름 입력·생성 버튼 클릭·영상 단계 이동을 확인했다. 생성 API 응답은 목업이며 버튼 겹침이나 클릭 차단이 없음을 확인하는 검사다.
- 첫 운영 검사에서 정보를 채운 뒤 영상 단계로 돌아갔다가 다음을 누르면 React가 같은 DOM 버튼을 submit으로 바꾸어 자동 초안 저장하는 문제가 발견됐다. `b9dcfbb` 배포 후 [롤백 38196859273](https://github.com/yoo9857/dreamcine/actions/runs/38196859273)으로 안정 버전 `d0c8e41` 복구, healthy·readiness 확인. QA 데이터는 제거됐다. 다음/등록 버튼에 다른 key를 주고 이동 버튼에 type=button·preventDefault를 적용했다. 이후 위 여섯 폭의 실제 브라우저 왕복 검사에서 저장 요청 0건을 확인했다. 저장소 시리즈 E2E에도 같은 재현 경로의 요청 횟수 검증을 추가했다.
- 저장소 시리즈 E2E를 새 단계 이동에 맞췄다. 전체 공개·예약 E2E 실행 완료 주장은 아니다.
- O01 Fast lane으로 관련 테스트·정적 검사 후 웹만 배포한다. 최종 배포 SHA·운영 저장 검사·서비스 상태는 `docs/HANDOFF.md`에 기록한다. 기존 공유 초기 JS의 Bundle budget 과제는 별도이며 이번에 예산을 변경하지 않았다.
