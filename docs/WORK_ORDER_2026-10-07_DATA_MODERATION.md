# 데이터 정합성과 회원 제재 개선

사용자 요구: PostgreSQL 적재·파일 연결 누락 확인 및 개선. 신고 누적 → 운영진 검토 → 경고 또는 24시간/3일/7일/15일/영구 정지. 신고 횟수만으로 자동 제재하지 않는다.

## 이번 작업의 검증 기준

- 업로드 완료 상태와 VideoAsset 연결을 DB 트랜잭션으로 저장하고 재시도·동시 완료를 방어한다.
- 신고 심사 결과, 대상 변경, 경고·정지, 감사 이력을 한 DB 트랜잭션으로 저장한다. 실패하면 신고가 REVIEWING 상태에 고착되지 않는다.
- 같은 대상의 신고 묶음을 잠그고 동시에 다른 운영자가 조치하지 못하게 한다.
- 관리자 계정과 자기 계정의 제재를 방어한다. 기간은 1/3/7/15일 또는 영구로 제한한다.
- 정지 시 모든 세션을 폐기한다. 초안·예약 게시 상태를 변경하지 않는다. 정지 소유자의 콘텐츠 접근은 조회 계층에서 차단한다.
- 만료된 기간 정지는 반복 작업과 로그인 시점 검사로 해제한다. 영구 밴은 자동 해제하지 않는다.
- 경고와 제재의 사유, 담당자, 전후 상태, 기간, 관련 신고 목록을 PostgreSQL에 남기고 관리자에서 검토한다.
- 파일·DB 연결 문제를 관리자 화면과 운영 점검에서 확인한다. 확인되지 않은 원인으로 기존 기록을 지우지 않는다.
- 이미지의 소유자·키·용량·포맷·최적화 메타데이터를 등록한다.
- 변경 범위의 단위·PostgreSQL 통합·권한·경합 검증을 수행한다. 전체 빌드나 운영 반영의 한계는 숨기지 않는다.

## 최초 운영 점검

영상 자산 7개 원본 존재, 공개 에피소드 6개 연결 정상, 좋아요·댓글 카운터 불일치 0건. UPLOADED 세션 3건은 자산·원본 모두 없음. 최근 30일 게시물이 없어 rankScore 모두 0. AuthAuditLog 0건. 정기 백업과 실제 복구 성공은 미확인.

시청 위치 평균을 실제 시청 시간으로 부르는 분석과 상세 행동 이벤트 적재, 오래된 콘텐츠의 추천 순위는 별도 개선 항목으로 기록한다. 이번 제재·데이터 정합성 작업의 완료 여부와 구분해서 보고한다.

## 구현 및 검증

- 신고는 누적 수와 위험 분류에 따라 검토 우선순위만 올린다. 운영진 확인 전 콘텐츠 숨김이나 정지를 실행하지 않는다.
- 같은 대상의 신고 결정은 PostgreSQL advisory lock으로 직렬화하고 관련 신고·조치·증거·알림을 한 트랜잭션으로 저장한다.
- 고정 정지 기간, 경고, 해제와 자동 만료 이력을 저장한다. 정지 시 로그인 세션과 진행 업로드를 차단한다. 초안 상태는 보존하고 공개 조회·재생·예약 공개에서 정지 소유자를 차단한다.
- 이미지 저장 성공 뒤 등록 메타데이터와 작품 연결을 한 트랜잭션으로 저장한다. WebP 실제 디코딩, 최대 40MP 입력 제한, 최대 2048px 출력, EXIF 제거, 해상도·크기·SHA256 등록을 적용한다. 아바타 키 변경은 소유권이 검증된 등록 이미지로 제한한다.
- 영상 업로드 상태와 에셋 연결을 원자적으로 저장한다. 저장소 완료 후 DB 연결 실패는 실제 파일 존재와 크기를 확인한 경우에만 재시도한다.
- 콘텐츠 삭제 요청은 PostgreSQL 조치 기록에 저장하고 큐 전송 실패 시 유지보수 작업이 재전송한다. 댓글 삭제는 댓글 카운터도 갱신한다.
- 관리자에 정합성 점검과 조치 이력을 추가했다. 이미지 등록 수는 기존 전체 이미지 수와 다르며 기존 객체의 자동 전수 등록·존재 검증은 아직 완료하지 않았다.
- 관련 서비스·스키마·이미지·큐·화면 검증 151개 통과. 분리된 PostgreSQL에서 기간 5종, 영구 유지, 만료 멱등성, 동시 신고, 실패 롤백, 증거 보존, 동시 업로드, 이미지 소유권 검증 12개 통과. 웹·워커 TypeScript 빌드 통과.

## 남은 분석 개선 범위

상세 행동 이벤트 수집, 개인화 추천, 실제 시청 시간 산출은 기존 구현에서 확인되지 않았다. 이번 변경으로 해당 기능까지 완성됐다고 주장하지 않는다. 기존 원본이 없는 업로드 3건은 복원 가능한 원본이나 삭제 이력을 확인하기 전 보존한다. 정기 백업 주기와 외부 보관 정책은 추가 운영 설정이 필요하다.
