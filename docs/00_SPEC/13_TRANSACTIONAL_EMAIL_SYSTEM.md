# ILOG 트랜잭션 메일 시스템

## 1. 목적

ILOG의 계정·결제·이벤트 메일은 동일한 브랜드 구조와 발송 정책을 사용한다.
HTML 메일을 지원하지 않는 환경을 위해 모든 템플릿은 같은 내용을 담은 plain text 본문을 함께 제공한다.

## 2. 공통 와이어프레임

├──────────────────────────────────────────────┤

│                                              │

## 3. 템플릿 카탈로그

| 유형 | 발송 시점 | 주요 CTA | 필수 정보 |
| --- | --- | --- | --- |
| 이메일 인증 | 이메일 가입 직후 | 이메일 인증하기 | 24시간, 일회용 링크 |
| 가입 축하 | 이메일 인증 완료 직후 | ILOG 둘러보기 | 핸들, 인증 상태 |
| 비밀번호 재설정 | 계정 복구 요청 시 | 비밀번호 재설정 | 1시간, 일회용 링크 |
| 환불 | 요청 접수·완료 시 | 없음 | 환불번호, 금액, 처리일시 |
| 이벤트 | 마케팅 수신 동의자 대상 | 이벤트 확인하기 | 일정, 수신 해제 링크 |

## 4. 발송 정책

- 계정·결제 메일에는 오픈 추적과 클릭 추적을 사용하지 않는다.
- 이벤트 메일은 명시적으로 수신에 동의한 회원에게만 발송하고 수신 해제 링크를 포함한다.
- 사용자·운영자 입력은 HTML 이스케이프 후 렌더링한다.
- 토큰, SMTP 자격증명, API 키는 로그와 템플릿에 기록하지 않는다.
- 링크는 항상 `APP_URL` 기반의 절대 HTTPS URL을 사용한다.
- 인증과 비밀번호 재설정 링크는 각각 24시간·1시간 동안 한 번만 사용한다.

## 5. 전달성 정책

- 발신 주소는 `noreply@ilog.info`를 사용한다.
- Resend용 DKIM·SPF·DMARC와 `send.ilog.info` Return-Path를 유지한다.
- 기존 Zoho 수신 MX와 Resend 발송 MX를 분리한다.
- 반송·불만 주소에는 재발송하지 않고 발송 서비스의 suppression 정책을 따른다.
- 새 도메인은 소량 트랜잭션 메일부터 시작해 발송 평판을 점진적으로 쌓는다.

## 6. 구현 위치

- 공통 레이아웃과 템플릿: `apps/web/src/lib/mail-templates.ts`
- SMTP 전송과 공개 발송 함수: `apps/web/src/lib/mail.ts`
- 템플릿 렌더링 검증: `apps/web/src/lib/mail-templates.test.ts`

## 7. 실제 연동 상태

| 흐름 | 상태 | 연결 위치 |
| --- | --- | --- |
| 이메일 가입 인증 | 연결 완료 | `services/auth/signup.ts` |
| 인증메일 재발송 | 연결 완료 | `services/auth/resend-verification.ts` |
| 가입 인증 후 환영메일 | 연결 완료 | `services/auth/verify-email.ts` |
| OAuth 신규 가입 환영메일 | 연결 완료 | `auth/adapter.ts` |
| 비밀번호 재설정 | 연결 완료 | `services/auth/request-password-reset.ts` |
| 환불 안내 | 템플릿·발송 함수 준비 | 결제·환불 모델과 처리 서비스 구현 후 연결 |
| 이벤트 안내 | 템플릿·발송 함수 준비 | 마케팅 동의 API·수신해제 화면·대상 조회 구현 후 연결 |

환불과 이벤트는 현재 원천 도메인 기능이 없으므로 자동 발송하지 않는다. 환불 처리 사실이나
마케팅 수신 동의를 추정해서 메일을 보내면 안 된다.

## 8. 배포 필수 조건

- 운영 `.env`에 `APP_URL`, `SMTP_URL`, `MAIL_FROM`을 함께 설정한다.
- `/api/ready`는 운영 환경에서 SMTP 설정이 빠지면 `checks.mail=fail`과 HTTP 503을 반환한다.
- 운영 가입 API는 SMTP 설정이 빠진 경우 계정을 생성하지 않고 실패한다.
- Resend 대시보드에서 `ilog.info`가 `Verified`인지 확인한다.
- 공개된 API 키는 폐기하고 새 `Sending access` 키로 교체한다.
